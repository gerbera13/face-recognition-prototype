1. ЦЕЛЬ РАБОТЫ
---------------------------------------------------------------------------
Разработать прототип программного обеспечения для биометрической
идентификации клиентов банка по лицу в режиме реального времени.

Система должна обеспечивать:
- регистрацию клиентов в базе по фотографии (enrollment);
- идентификацию клиента по видеопотоку с камеры (поиск 1:N);
- верификацию — проверку принадлежности лица конкретному клиенту (1:1);
- защиту от подмены фотографией (liveness detection);
- два интерфейса: десктопное приложение и веб-интерфейс.

Ограничение: использовать только библиотеку OpenCV (без dlib,
без face_recognition, без нейросетевых SDK).

---------------------------------------------------------------------------
2. ЧТО СДЕЛАНО (РЕЗУЛЬТАТЫ)
---------------------------------------------------------------------------
2.1. Ядро системы — модуль bank_face_system.py
Реализован полный конвейер (pipeline) распознавания:

    камера/фото -> детекция лица -> извлечение признаков ->
    -> сравнение с базой -> вердикт «КЛИЕНТ» / «НЕ ОПОЗНАН»

Компоненты:

1) Детектор лица (класс FaceDetector) — мульти-каскадный Haar-детектор
   (5 каскадов + CLAHE-эквализация). Многоэтапная стратегия поиска:
   - этап 1: строгий фронтальный каскад (полное лицо);
   - этап 2: каскад alt2 (устойчив к вариациям);
   - этап 3: ослабленные параметры для частично скрытого лица
     (маска, шапка);
   - этап 4: детекция глаз с восстановлением области лица по глазам
     (для лиц в маске);
   - этап 5: профильный каскад;
   - этап 6: «последний шанс» — очень мягкие параметры.

2) Извлечение признаков (класс FeatureExtractor) — комбинация трёх
   методов для надёжности:
   - LBP-гистограммы по сетке 8x8 (текстура лица);
   - упрощённый HOG-дескриптор (форма лица);
   - HSV-цветовые гистограммы (общий тон кожи);
   - отдельный вектор признаков для верхней 60% лица (глаза, лоб,
     брови) — используется при распознавании в маске.

3) Сравнение — косинусное сходство (cosine similarity) векторов
   признаков, порог сходства по умолчанию 0.5.

4) Ядро (класс FaceBank):
   - enroll() — регистрация клиента по фото (ID + ФИО);
   - identify() — поиск по всей базе (1:N), сравнение и полного лица,
     и верхней части (для маски);
   - verify() — верификация 1:1 по ID клиента;
   - save()/load() — сохранение и загрузка базы (Pickle-файл
     facebank_db.pkl);
   - list_customers(), customer_count — работа со списком клиентов.

5) Защита от подмены (класс LivenessDetector) — анализ движения между
   кадрами (разность кадров, порог по проценту изменившихся пикселей).

6) Визуализация (draw_result) — вывод рамки вокруг лица и статуса
   «КЛИЕНТ: <ФИО>» (зелёный) или «НЕ ОПОЗНАН» (красный) с процентом
   совпадения.

2.2. Десктопное приложение — demo.py
Консольное приложение с выводом видеопотока через окно OpenCV.
Управление клавишами:
  E — регистрация клиента, L — список клиентов,
  S — сохранение базы, Q — выход.

2.3. Веб-интерфейс — web_server.py + templates/index.html
Локальный веб-сервер на Flask (порт 8080). Возможности:
- просмотр видео с камеры в реальном времени в браузере;
- отображение результата распознавания («КЛИЕНТ» / «НЕ ОПОЗНАН»)
  с процентом совпадения;
- регистрация клиентов через веб-форму (ID + ФИО);
- просмотр списка клиентов в базе.

Архитектура веб-версии:
- Frontend: HTML5 + JavaScript, камера через getUserMedia, кадры
  отправляются на сервер каждые 600 мс в base64;
- Backend: Flask REST API (/api/identify, /api/enroll, /api/customers,
  /api/save, /api/status);
- на серверной стороне используется тот же модуль
  bank_face_system.py.

2.4. База данных
- Формат: Pickle-файл facebank_db.pkl (локальная БД клиентов).
- Клиент (Customer): ID, ФИО, вектор признаков полного лица, вектор
  верхней части лица, путь к фото, дата регистрации.
- Порог сходства хранится в базе.

5. ОГРАНИЧЕНИЯ ПРОТОТИПА
---------------------------------------------------------------------------
- Точность: Haar cascade + LBP уступает нейросетевым решениям
  (InsightFace, ArcFace) в 2-3 раза.
- Маски/шапки: детектор с fallback на детекцию глаз (6 этапов),
  но надёжность ниже, чем у нейросетевых детекторов.
- Освещение: чувствителен к резким перепадам освещения
  (компенсируется CLAHE).
- Масштабирование: Pickle не подходит для баз более ~1000 клиентов
  (линейный перебор).
- Безопасность: нет шифрования биометрических данных, нет
  аттестованного хранилища (требование 152-ФЗ).
- Liveness: только анализ движения, не защищает от 3D-масок
  и видеоподмены высокого качества.

8. ВЫВОД
---------------------------------------------------------------------------
Прототип системы распознавания лиц для банка разработан и работает.
Реализованы все заявленные функции: детекция лица в реальном времени,
регистрация клиентов, идентификация (1:N), верификация (1:1),
liveness-проверка, два интерфейса (десктопный и веб). Система
построена на базе OpenCV без внешних нейросетевых зависимостей.

Дальнейшие шаги — переход на нейросетевой стек (YuNet + ArcFace),
промышленный liveness (anti-spoofing), микросервисная архитектура
и векторная БД, а также выполнение требований законодательства
(152-ФЗ, ЕБС) перед вводом в эксплуатацию.
