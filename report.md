# Система распознавания лиц для банка — Отчёт

## 1. Назначение системы

Прототип системы биометрической идентификации клиентов банка по лицу в режиме реального времени. Система позволяет:
- Регистрировать клиентов в базе (enrollment)
- Опознавать клиентов по видеопотоку (identification 1:N)
- Проверять принадлежность лица конкретному клиенту (verification 1:1)
- Определять «живость» лица (liveness detection)

## 2. Техническая архитектура

| Компонент | Технология | Назначение |
|---|---|---|
| Детекция лиц | Multi‑Cascade Haar (5 каскадов + CLAHE) | Поиск лица с учётом маски/шапки |
| Извлечение признаков | LBP + HOG + HSV-гистограмма | Формирование вектора признаков |
| Сравнение | Cosine similarity | Поиск ближайшего в базе (1:N) |
| Liveness | Motion detection (разность кадров) | Защита от фото/видео-подмены |
| Хранение | Pickle-файл | Локальная БД клиентов |

## 3. Интерфейсы

### Десктопное приложение (demo.py)
Консольное приложение с выводом видеопотока через OpenCV GUI. Управление клавишами: E — регистрация, L — список, S — сохранение, Q — выход.

### Веб-интерфейс (web_server.py)
Локальный веб-сервер на Flask (порт 8080). Доступ через браузер. Позволяет:
- Просматривать видео с камеры в реальном времени прямо в браузере
- Видеть результат распознавания (КЛИЕНТ / НЕ ОПОЗНАН) с процентом совпадения
- Регистрировать клиентов через веб-форму (ID + ФИО)
- Просматривать список клиентов в базе

Запуск: `python3 web_server.py`, открыть http://localhost:8080

**Архитектура веб-версии:**
- **Frontend**: HTML5 + JavaScript, камера через `getUserMedia`, кадры отправляются на сервер каждые 600 мс в base64
- **Backend**: Flask REST API (`/api/identify`, `/api/enroll`, `/api/customers`, `/api/save`)
- Та же библиотека `bank_face_system.py` используется на серверной стороне

## 4. Ограничения прототипа

- **Точность**: Haar cascade + LBP уступает нейросетевым решениям (InsightFace, ArcFace) в 2-3 раза
- **Маски/шапки**: Мульти-каскадный детектор с fallback на детекцию глаз (6 этапов)
- **Освещение**: Чувствителен к резким перепадам освещения
- **Масштабирование**: Pickle не подходит для >1000 клиентов
- **Безопасность**: Нет шифрования биометрических данных

## 5. Дорожная карта до продакшена

1. Заменить детектор на **YuNet** (OpenCV DNN) или **RetinaFace**
2. Заменить признаки на **InsightFace / ArcFace** (нейросетевые эмбеддинги)
3. Liveness → **Face Anti-Spoofing** (Silent-Face-Anti-Spoofing)
4. Микросервис на **FastAPI** + **Redis** для кеша сессий
5. Векторная БД **Milvus** / **Qdrant** для быстрого поиска
6. Шифрование биометрии (AES-256), хранение ключей в HSM
